## 1. 관계 모델 전환 — 팔로우 → "단골"

**결정:** 일반 소셜의 "팔로우/팔로워"를 그레이드 고유의 **"단골"(EN: Regular)** 로 대체한다. 단골은 *근거 기반 신뢰 표시* 다 — 그 리뷰어의 리뷰가 실제로 맞았다고 내가 확인해야만 맺을 수 있다.

### 성립 조건 — "적중(hit)"
같은 리뷰어에게 **적중이 쌓이면** 그 리뷰어의 "단골 맺기"가 열린다. 적중으로 인정되는 행동:
1. **구매 적중** — 리뷰의 추적/구매 링크로 구매 후 "리뷰대로였나요?"에 "맞았어요"
2. **도움 적중** — 저장(레퍼런스)한 리뷰를 다시 열었을 때 "도움됐나요?"에 "도움됐어요"

같은 리뷰(videoId)당 적중 1회만 인정(중복 제거).

### 노출 정책 (2026-09-18 조정)
- 초기 설계는 "적중 2회 → 해제 + 잠금 상태 노출"이었으나, **"아직 단골을 맺을 수 없어요" 잠금 카피가 이상하다**는 피드백.
- **변경 방향:** 단골 버튼을 기본 숨김 → **구매/적중이 한 번이라도 발생하면 그때 버튼이 등장**하는 방식으로 전환. (잠금 UI 없이 "생기면 뜬다")

### 데이터
- 관계 저장은 **기존 팔로우 API 재사용**(서버 변경 없음). "단골"은 클라이언트 표현·게이트 레이어.
- 적중 기록·판정은 기기 로컬(`api/regulars.js`, prefSafe). 서버 복구 시 동기화.
- **기존 팔로우 관계는 전부 단골로 승계**(삭제·잠금 소급 없음).

### 화면
- 홈 카드 버튼(단골 맺기/단골), 홈 스토리 레일 단골 우선 노출, 마이 탭 "나의 단골" 진입 카드, 팔로우 목록 라벨 교체("나를 단골로 둔 사람 / 나의 단골").

### 2단계(미착수)
받은 단골 수의 G점수 반영, 서로단골 승격 — 서버 배포 + 어뷰징 방어 설계 후.

> 정본 설계: `docs/superpowers/specs/2026-09-17-dangol-relationship-design.md`

## 2. 커머스 · 판매자 생태계

**결정:** 자사몰이 없는 회사는 그레이드 안이 곧 스토어, 자사몰이 있는 회사도 같은 스토어를 쓰되 외부몰로 나갈 수 있게 한다. 외부 이동은 로그로 남겨 그레이드 귀속 인센티브의 근거로 삼는다.

### 2-1. 외부몰 추적 이동 ("모든 상품 보러가기")
- 상품에 외부몰 링크가 있으면 상품 페이지·판매자 스토어에 **"모든 상품 보러가기 ↗"** 노출.
- 클릭 시: ① `outbound_click` 이벤트 즉시 기록 ② 정산용 로컬 큐 적재 ③ 외부 URL에 `utm_source=greyd&greyd_uid=<유저>` 부착.
- **서버 대기:** 외부몰 실제 전환(구매) 귀속·인센티브 정산.

### 2-2. 판매자 모드 전환
- `FEATURES.BRAND_APP` 재개방(8/11 "브랜드는 웹 전용" 결정을 대체).
- 판매자 계정: 마이 탭 → "판매자 모드로 전환" → 브랜드 셸(대시보드·리뷰 평가·마이)로 재시작. 역방향 복귀 가능.

### 2-3. 앱내 상품 등록 + 스토어
- 브랜드 셸에 "내 상품 관리 / 상품 등록" 진입. 등록은 기존 `AddingNewProduct` 화면·API 재사용.
- 판매자 스토어 화면(`screens/StoreScreen`: SellerStore·StoreCatalog·StoreProduct·StoreOrders·StoreWeb) 구성.

### 2-4. 제품 뿌리기 (FGI/리뷰 캠페인 배포 요청)
- 판매자가 앱에서 캠페인 이름·수량·보상P·기간·**FGI 포함 여부**를 입력해 배포 요청.
- 전송: ops 아웃박스 → **ops 수신 엔드포인트 `/api/mobile/brand/campaigns`** (EventLog `brand.campaign_request` + 콘솔 알림, 재전송 dedupe). **배포 완료**.

### 2-5. 판매자 웹 포털
- ops `/portal/store/[token]` 상품 등록 포털 — **프로덕션 배포 완료**. 앱/웹 어느 쪽에서도 상품 등록 가능.

> 정본 설계: `docs/superpowers/specs/2026-09-17-brand-store-design.md`, `docs/commerce-and-seller-2026-09-16.md`

## 5. 쇼츠 UX 개편

**피드백:** 리뷰 요약이 기본 노출돼 영상 절반이 가려짐 / 닫기 버튼이 너무 작음 / 나갈 길이 없음.

- **리뷰 요약 기본 숨김** — 영상만 깨끗하게, 좌하단 작은 핸들("@작성자 · 리뷰 보기")만 노출. 탭하면 요약 등장.
- **닫기 = 카드 우측 상단 큰 X** (작은 ✕ 대체) + **영상 아무 데나 탭하면 요약 자동 닫힘**.
- **상단 뒤로가기** 버튼 추가(홈 카드에서 진입한 쇼츠 탈출로).
- **좌우 스와이프(예정/진행 중):** 우측 스와이프 → 전 화면, 좌측 스와이프 → 홈. (세로 페이저와 충돌 없이 구현 중)

## 6. 디자인 방향 전환 — 웜 골드 글래스모피즘

**결정:** 여성 타깃 세련된 톤. 레퍼런스 3종(골드 글래스 로그인 · 유리 버튼 · 프로스트 메뉴) 반영.

- **배경:** 차가운 회색(#F4F4F4) → **웜 크림(#F3EDE2)**. 레거시 화면 배경까지 정렬.
- **골드 오브:** 화면 뒤에 떠 있는 골드 그라데이션 구체 3개(`GlassOrbs`) — 전 주요 화면.
- **유리 카드:** 공용 `Card`/`GlowCard`에 **진짜 배경 블러**(`@react-native-community/blur`) 적용 — 뒤 오브·배경이 흐려져 비친다. (반투명만으로는 "유리 같지 않다"는 피드백 반영 → 네이티브 블러 도입)
- **버튼:** 알약(pill) + 광택 그라데이션. **탭바:** 웜 반투명 + 아이콘 한 세트(MCI, 아웃라인/채움·앰버 포커스)로 통일.
- **댓글 시트·입력 모달:** 프로스트 글라스(영상이 뒤로 흐려짐).
- **주의:** 블러는 네이티브 의존 → iOS는 빌드 234부터 반영, 이후 변경은 네이티브 재빌드 필요.

> 함정 기록: PowerShell `Get-Content -Raw | -replace | Set-Content`는 한글 주석 인코딩을 깨뜨린다 → 한글 파일은 Edit/sed로만.

## 7. 파이프라인 연결성 (단절 수리 + 예시 데이터)

**원칙:** 모든 과정은 연결된 여정. 기계 검사(미등록 라우트·문자열 누락) + 흐름 검사(참여~보상, 커머스~판매자) 재실행.

- **수리:** 주문 상세(OrderPage) 신설, FGI 설문 후 복귀 경로, 마이 탭 2차 활용 진입, 진행 상황 타임라인(검수 중·FGI 상태), 첫인상 설문→업로드 연결, 홈 TODO 카드 단계 직행, 지급 완료 상세.
- **예시 데이터:** 마켓/스토어가 비어 보이지 않게 "(예시)" 주문·상품 카드(실데이터 생기면 자동 대체). ops 시딩 캠페인을 앱 노출(`applyMode=open`)로 채움 — 자격 미달자는 신청 단계에서 걸러짐(정상).
- **홈 카드 버튼:** "이걸 참고해서 올리기" → **"구매하러 가기"**(연결 상품 직행). "참고해서 올리기"는 저장(책갈피)→리뷰 상세의 히든 동선으로 이동.
- **검증 결과:** 미등록 라우트 0 · 문자열 누락 0 · 테스트 160 통과 · 번들 컴파일 성공. 남은 것은 단절이 아니라 **서버 의존 순서**.
