# 그레이딩(G-스코어) 재설계 — 시청자 평가 폐지, 균형 다축 (2026-09-20)

## 배경·결정

기존 그레이딩은 두 갈래였다: (1) 고정 델타 G-스코어(완료 +3·스트라이크 -10), (2) 시청자가 리뷰를 6축(표현력·재미·매력도·정보성·영상미·독창성)으로 별점 주는 G6. 9/20 전략 회의 결정:

- **시청자 별점 폐지.** 가짜 리뷰(시딩) 안에서 시청자가 영상 퀄리티를 별점 주는 건 무의미 — 예쁜 연예인이 이김. 리뷰 목적과 어긋남.
- **크리에이터를 균형 다축으로 스코어링.** 브랜드사 평가 · 판매 전환 · 영상 정성 · 성실성을 **동일 비중(각 25%)** 으로 합산.
- **먹튀(수령 후 미업로드)는 3회 유예** 후 신청 제한.
- **G6 데이터·코드는 보존**(기능 보존 원칙), 입력 UI만 숨김. 나중에 브랜드용 랭킹 데이터로 재활용 여지.

## 새 G-스코어 공식

4개 하위 점수(각 0~100)를 동일 가중으로 합산해 0~100으로 만든다. 데이터가 없는 축은 중립(50)으로 시작해 신규 크리에이터가 배제되지 않게 한다.

```
gScore = round( 0.25*brand + 0.25*sales + 0.25*effort + 0.25*reliability )   # 0~100
```

기존 호환 유지: `CURATED_MIN_G = 60`(선정 해제), `gradeMultiplier`(포인트 배수), `concurrentLimit`(동시 한도)는 그대로. 새 공식이 gScore 값을 만들고, 이들 함수는 그 값을 계속 소비한다.

### 하위 점수 정의 (`api/gscore.js`)

1. **brand (브랜드사 평가)** — 캠페인 후 브랜드가 매긴 루브릭(authenticity·delivery·quality·marketSignal, 각 1~5) 평균 ×20 → 0~100, 재협업(rebook) true면 +10(상한 100). 평가 이력 평균. 없으면 50.
2. **sales (판매 전환)** — 그레이드 경유 실구매·추적 신호. 현재 재료: 단골 적중(구매형), 추적코드 전환, 외부몰 클릭, 공동구매 참여, (서버 연결 시 주문). 정규화 함수로 0~100, 신호 없으면 50. *판매 불가 국가 크리에이터는 여기서 불리하지만 균형 가중이라 브랜드·정성·성실로 보완.*
3. **effort (영상 정성)** — 리뷰 영상 길이 기반. <30s→20, 30~59s→40, 60~119s→70, ≥120s→100 (회의 예: 30초 1점 / 2분 5점). 여러 편이면 평균. duration 없으면 50.
4. **reliability (성실성)** — 정시 완료율·유예·스트라이크. 기준 100에서 스트라이크당 감점, 유예 완주는 부분 인정. onTimeRate 반영. 스트라이크 3회면 `isApplicationBlocked = true`(신규 신청 제한).

상수: `WEIGHTS = {brand:.25, sales:.25, effort:.25, reliability:.25}`, `STRIKE_LIMIT = 3`, `EFFORT_TIERS`, `NEUTRAL = 50`.

## 클라이언트/서버 경계

- gScore 정본은 서버 `/me`. `api/gscore.js`는 **정본 공식**을 코드로 고정해 (a) 서버 값이 없을 때 낙관적 로컬 표시, (b) ops가 미러링할 계약으로 쓴다.
- **brand·sales의 실데이터는 서버(ops) 재계산 의존** — 내 기기엔 "나를 평가한 브랜드 점수"나 "내 리뷰로 발생한 타인의 구매"가 없다. 클라이언트는 서버 제공 전까지 중립(50)으로 두고, effort·reliability는 로컬 신호로 즉시 계산.
- ops 연결 시: 브랜드 평가(evaluations)·주문 귀속을 서버가 집계해 gScore 재계산 → `/me`로 내려줌. (별도 ops 작업, greyd-ops는 우리가 직접 개발)

## 시청자 평가(G6) 처리

- `FEATURES.VIEWER_RATING = false` 신설. off면 `RatingButton`(영상 우하단 진입)·`RatingModalView` 미노출.
- `ReviewGradeBadgeView`·`RatingList`·`g6RatingVideo` API·비디오 g6 필드는 **삭제하지 않는다.** 기존 데이터가 있으면 배지는 계속 보이되 신규 입력만 막는다.

## 영상 정성 재료 확보

- 업로드 플로우(`UploadVideo.onSuccess`)에 이미 `duration`이 있다 → 리뷰 업로드 페이로드에 `durationSec`를 실어 저장(서버 필드 추가 대상). 없으면 effort=50 중립.

## UI 변경

- **마이 탭:** "신뢰 구성요소" 카드를 G-스코어 4축 구성으로 재구성 — 브랜드·판매·정성·성실을 막대/수치로. "무엇이 G-스코어를 만드나" 설명.
- **영상 화면:** 시청자 별점 버튼 제거(플래그).
- 활동 탭 gProgressRatio 진행바는 유지(값만 새 공식 기반).

## 구현 순서

1. `api/gscore.js` + `api/gscore.test.js` — 공식·하위점수·먹튀 게이트. (정본, 테스트 우선)
