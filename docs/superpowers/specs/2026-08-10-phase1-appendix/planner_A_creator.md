# greyd 1단계 — 크리에이터 여정 고도화 설계

전제: 클로즈드 시딩 앱의 1단계 성공 지표는 "초대받은 인플루언서가 **첫 시딩을 D+30 내 업로드까지 완주**하고, **두 번째 캠페인을 신청**하는 것"이다. 아래 모든 설계는 이 완주율(Seeding Completion Rate)과 재신청률(Repeat Apply Rate)을 끌어올리는 방향으로 정렬했다.

스코프 표기: `[1단계]` 지금 구현(클라이언트/mock 가능) · `[2단계]` 다음 릴리즈 · `[서버]` 백엔드 필요(1단계는 mock/수동 운영으로 대체)

---

## 1. 크리에이터 여정 맵 (8단계)

### 1-0. 여정 전체 흐름과 핵심 KPI

```
초대 수령 → 게이트 통과 → SNS 연결 → 첫 신청 → 승인 → 배송/수령 → 촬영/업로드 → 보상 → 재참여
   (K1)        (K2)                  (K3)      (K4)              (K5)          (K6)     (K7)
```

| KPI | 정의 | 목표(가설) |
|---|---|---|
| K1 초대 전환율 | 초대 링크 클릭 → 가입 완료 | 60% |
| K2 활성화율 | 가입 → 72시간 내 첫 신청 | 50% |
| K3 승인율 | 신청 → 승인 (운영 통제 변수) | 40~60% |
| K5 완주율 | 제품 수령 → 마감 내 업로드 | **80% 이상 (핵심)** |
| K7 재신청률 | 첫 완주 → 14일 내 2번째 신청 | 60% |

## 2. 신청 자격 / 승인 정책

### 2-1. 캠페인 2-트랙 구분 (회의의 "신규 물량 vs 승인 물량" 구체화)

| | **Open 캠페인** (신규 진입용) | **Curated 캠페인** (검증 크리에이터용) |
|---|---|---|
| 목적 | 신규 크리에이터의 첫 완주 경험 + 그레이딩 시드 데이터 | 브랜드가 돈 주고 사는 품질 UGC |
| 자격 | 팔로워 0명도 가능. SNS 핸들 연결만 필수 | 그레이딩 37.0° 이상 **또는** 완주 이력 2회 이상 |
| 승인 방식 | 선착순 자동 승인(물량 소진까지). 1인당 동시 진행 1건 제한 | 브랜드/운영 수동 승인 (어필 문구 + 프로필 검토) |
| 물량 배분 제안 | 캠페인 전체 물량의 20~30% | 70~80% |
| 포인트 | 기본가 (예: 200P) | 기본가 + 그레이딩 보정 (§4) |
| 목록 표기 | `Open · 선착순 12개 남음` 초록 배지 | `Curated · 승인 필요` + 자격 미달 시 잠금 표시: "37.0° 달성 시 신청 가능" |
| 스코프 | 배지+선착순 카운트 mock `[1단계]`, 실 선착순 `[서버]` | 잠금 UI+자격 로직(로컬 그레이딩 값 기준) `[1단계]`, 수동 승인 콘솔 `[2단계][서버]` |

**핵심 의도**: Curated 잠금이 보이는 것 자체가 그레이딩을 올리고 싶은 욕구를 만든다. 잠금 캠페인을 숨기지 말고 **보여주되 잠가라.**

### 2-2. 동시 진행 한도 (먹튀 리스크 상한)

| 그레이딩 | 동시 진행 가능 캠페인 |
|---|---|
| 신규(이력 0) | 1건 |
| 36.5°~37.9° | 2건 |
| 38.0° 이상 | 3건 |

한도 도달 시 신청 버튼: "진행 중인 리뷰를 완료하면 신청할 수 있어요" `[1단계]` (로컬 카운트)

### 2-3. SNS 검증 — 1단계 mock 수준에서 가능한 것

| 방식 | 내용 | 스코프 |
|---|---|---|
| 핸들 형식 검증 | @포함, 존재 가능한 형식인지 로컬 정규식 | `[1단계]` |
| 자가 신고 + 서약 | 팔로워 수 자가 입력 + "허위 기재 시 그레이딩 하락" 문구 | `[1단계]` |
| 프로필 링크 열람 | 운영자가 승인 시 수동 확인(앱은 링크만 저장) — 클로즈드 초기엔 이걸로 충분 | `[1단계]` 운영 |
| 바이오 코드 인증 | 인스타 바이오에 `greyd-X4F2` 임시 코드 삽입 → 운영 확인 (계정 소유 증명) | `[2단계]` |
| OAuth 실연동 | 인스타 Basic Display / 틱톡 Login Kit | `[2단계][서버]` |

### 2-4. 주소 수집 시점 — **승인 후, 가입 시 아님**

이유 3가지: (1) 온보딩 입력 부담 최소화 (2) 개인정보는 필요 시점에만(글로벌 대상이라 GDPR류 민감) (3) "승인됐으니 주소를 달라"는 순서가 심리적으로 자연스럽고 입력 완료율이 높다. 2번째 캠페인부터는 저장된 주소 원탭 확인. `[1단계]` 로컬 저장, 암호화 저장은 `[서버]`.

## 3. 먹튀 방어 시스템

### 3-1. 타임라인과 리마인더 시퀀스 (수령 확인 = D0, 마감 = D+14)

| 시점 | 채널 | 카피 예시 | 톤 |
|---|---|---|---|
| D0 (수령 확인) | 인앱 | "타이머 시작! 8/17까지 업로드하면 300P를 받아요" | 긍정 |
| D+7 | 푸시 | "리뷰 마감까지 절반 지났어요. 15초 언박싱 영상도 좋아요 🎬" | 허들 낮추기 |
| D+11 (D-3) | 푸시+인앱 배너 | "3일 남았어요. 어렵다면 마감을 7일 연장할 수 있어요" (연장 버튼 노출) | 출구 제공 |
| D+13 (D-1) | 푸시 | "내일 마감돼요. 미업로드 시 300P가 사라지고 그레이딩이 내려가요" | 손실 프레임 |
| D+14 (마감) | 푸시 | "마감됐어요. 48시간 내 업로드하면 아직 인정돼요 (포인트 -30%)" | 유예 |
| D+16 | — | 미이행 확정 → 페널티 적용 | — |

스코프: 인앱 D-day 뱃지·배너 `[1단계]`, 로컬 노티 스케줄링 `[1단계]`, 서버 푸시 `[서버]`.

**설계 포인트**: 마감 직후 즉시 차단이 아니라 **48시간 유예 + 포인트 감액**(300P→210P)을 둔다. "늦었지만 올리는" 크리에이터를 살리는 게 브랜드에도 이득이다.

### 3-2. "1회 용인" 규칙의 구체화 — Strike 시스템

| 상태 | 조건 | 결과 | 표시 |
|---|---|---|---|
| Strike 0 | 정상 | — | — |
| **Strike 1** (1회 용인) | 수령 후 D+16까지 미업로드 | 그레이딩 **-1.0°**, 30일간 Curated 신청 잠금, 해당 캠페인 포인트 0 | 프로필에 본인만 보이는 경고: "약속 미이행 1회 — 한 번 더 발생하면 계정이 정지돼요" |
| **Strike 2** | 2번째 미이행 | **영구 차단** (초대 코드 무효화, 재가입 불가) + 브랜드사 리포트에 익명 처리 | 차단 화면: "약속된 리뷰가 두 차례 이행되지 않아 greyd를 더 이용할 수 없어요" |
| Strike 소멸 | Strike 1 이후 **연속 3회 완주** | Strike 0 복귀 (그레이딩 감점은 별도 회복) | "신뢰가 회복됐어요" 알림 |

**Strike로 치지 않는 것** (억울함 방지 — 이게 없으면 커뮤니티가 죽는다):
- 승인 후 주소 미입력 자동 취소 (제품을 안 받았으므로)
- 배송 분실/파손 신고 (사진 제출, 캠페인당 1회 인정) `[2단계]`
- 마감 연장 사용 후 연장 기한 내 업로드

스코프: Strike 상태 로컬 관리+경고 UI `[1단계]`, 실제 차단·코드 무효화 `[서버]`.

## 4. 보상 설계

### 4-1. 포인트 산정 공식

```
지급 포인트 = Base × Grade multiplier × Quality bonus
```

| 요소 | 값 | 설명 |
|---|---|---|
| **Base** | 캠페인별 100~500P (제품가·요구 공수 기준. 예: 세럼 1개+15초 영상 = 200P, 3종 세트+60초 = 400P) | 브랜드가 설정 |
| **Grade multiplier** | 36.5° 미만 ×1.0 / 36.5~37.9° ×1.1 / 38.0~38.9° ×1.25 / 39.0°+ ×1.5 | **회의의 "네고 대체" 구현**: 같은 캠페인 카드가 사람마다 다른 포인트로 표시 |
| **Quality bonus** | 브랜드가 done 처리 시 별점 4~5점이면 +20% | 품질 인센티브, §5 훅과 연결 |
| 감액 | 유예 기간(D+14~16) 업로드 시 ×0.7 | §3 |

**표시 방식** — 네고 대체 매칭의 UI 구현이 핵심:
- 캠페인 카드: `300P` 옆에 `내 등급 보너스 +30P` 초록 태그. 자격 미달 유저에겐 `기본 300P · 38.0° 달성 시 375P` 로 **올랐을 때의 금액을 미리 보여준다** (업그레이드 욕구 자극)
- 상세 페이지: "이 포인트는 당신의 그레이딩(37.2°)이 반영된 금액이에요"

스코프: 공식 계산+차등 표시(로컬 그레이딩 값) `[1단계]`, Quality bonus 실지급 `[서버]`.

### 4-2. 그레이딩(온도) 변동 규칙 제안

| 이벤트 | 변동 |
|---|---|
| 시작값 | 36.5° |
| 완주 (기한 내 업로드+done) | +0.3° |
| 브랜드 별점 5점 | 추가 +0.2° |
| 유예 업로드 | +0.1° |
| Strike 1 | -1.0° |
| 90일 무활동 | -0.2° (완만한 감쇠, 2단계) |

`[1단계]` 로컬 계산, 감쇠는 `[2단계][서버]`.

### 4-3. 현금화 없이 동기부여 — 1단계 사용처

| 사용처 | 비용 | 심리 | 스코프 |
|---|---|---|---|
| **부스트 신청**: Curated 캠페인 신청 시 50P로 "내 신청을 브랜드 목록 상단에 고정" | 50P | 승인 확률에 포인트를 태우게 함 → 포인트가 즉시 유용해짐 | `[1단계]` UI, 실 정렬 `[서버]` |
| **마감 추가 연장권**: 기본 1회 외 추가 연장 | 100P | 먹튀 방어와 시너지 (차단당하느니 포인트 소모) | `[1단계]` |
| **프로필 배지**: "Early Member", "5연속 완주" 등 장식 구매/획득 | 30~100P | 클로즈드 커뮤니티 지위재 | `[2단계]` |
| **잔액 이월 + 예고**: "포인트는 곧 현금 인출·제품 구매에 사용할 수 있어요 (2026 Q4 예정)" 배너 | — | 적립 자체를 저축으로 인식시킴. **날짜를 박아서** 신뢰 확보 | `[1단계]` 배너 |

핵심: 1단계에서 포인트의 1차 가치는 환금성이 아니라 **"더 좋은 캠페인에 접근하는 화폐"**로 정의한다. 그레이딩(자격)과 포인트(소모성 부스터)의 역할을 분리하면 둘 다 의미가 생긴다.

## 5. 리텐션 훅 (클로즈드 앱의 DAU 장치)

### 훅 1 — 브랜드 피드백 카드 ("누가 나한테 점수 줬지" 심리) `[1단계 mock / 실데이터는 서버]`
- done 시 브랜드가 남긴 **별점 + 한 줄 코멘트**가 카드로 도착. 푸시는 내용을 숨긴다: "[브랜드]가 당신의 리뷰를 평가했어요 — 지금 확인" (열어야만 보임)
- Activity 탭에 "받은 평가" 서랍. 별점 5점 카드는 공유 가능한 이미지로 저장(→ 크리에이터가 자기 인스타 스토리에 올리면 그 자체가 greyd 바이럴)
- 1단계: 승인 시 운영자가 코멘트 수동 입력, 앱은 mock 데이터로 카드 UI 완성

### 훅 2 — 신청 현황 라이브 카운트 (희소성 리프레시) `[1단계 mock]`
- Open 캠페인 카드에 `선착순 12/50 남음`이 줄어드는 표시 + 신규 캠페인 드롭 요일 고정(**매주 화·금 오전 "Drop"**). "매주 화·금엔 앱을 열어봐야 한다"는 습관 회로를 만든다. 클로즈드 앱 DAU는 상시 콘텐츠가 아니라 **정기 드롭**으로 만드는 게 정석(무신사 래플, 스니커즈 드롭 모델)
- 드롭 전날 푸시: "내일 오전 10시, 새 캠페인 4개가 열려요"

### 훅 3 — 그레이딩 변동 알림 + 다음 잠금 해제까지의 진행바 `[1단계]`
- 온도 변동이 있을 때마다 알림: "37.1° → 37.4° 상승! Curated 캠페인 해제까지 0.6° 남았어요"
- 프로필 상단에 진행바: `[■■■■■□□] 38.0°까지 -0.6° · 다음 혜택: 포인트 ×1.25`
- 당근 온도의 검증된 패턴 + 명확한 다음 보상 = 목표 그라디언트 효과

## 6. 1단계 구현 우선순위 요약 (지금 코드 작업 대상)

| 순위 | 항목 | 이유 |
|---|---|---|
| 1 | 신청 서약 체크박스 + 수령 확인 버튼 + D-day 카운트다운 | 먹튀 방어의 뼈대. 상태 5단계에 `received` 개념 추가 필요 (shipped와 reviewing 사이) |
| 2 | 승인 후 주소 모달 (48h 데드라인 문구 포함) | 여정의 실제 구멍. v1에 없음 |
| 3 | Open/Curated 배지 + Curated 잠금 UI + 그레이딩별 차등 포인트 표시 | 피벗의 차별 정책이 눈에 보이는 지점 |
| 4 | Strike 경고 UI + 마감 연장 1회 + 로컬 리마인더 노티 | 정책의 클라이언트 절반 |
| 5 | 브랜드 피드백 카드(mock) + 그레이딩 진행바 | 리텐션 훅, mock으로 완성 가능 |

서버 없이는 불가능해서 1단계에서 **문구·mock으로만 존재해야 하는 것**: 실제 자동 취소/자동 승인/차단 집행, 서버 푸시, 실 선착순 재고, OAuth 검증, 포인트 현금화. 이들은 클로즈드 초기 물량(수십~수백 건)이라 **운영자 수동 처리 + 앱은 UI 완성** 조합으로 충분히 굴러간다 — 이게 클로즈드 베타의 이점이다.

### 마지막 제언 (시니어 관점 리스크 3개)

1. **"솔직한 리뷰"와 포인트 보상의 긴장** — 브랜드 별점이 포인트에 영향을 주면(Quality bonus) 크리에이터는 좋은 말만 쓴다. Quality bonus는 "솔직함"이 아니라 **영상 완성도**(가이드 준수, 화질, 길이) 기준임을 카피에 명시할 것. 비추천 데이터 축적 정책과 정합성 유지.
2. **글로벌 배송 리드타임** — 한국→해외 배송 2~3주면 D+14 타이머의 체감이 국가마다 다르다. 타이머는 반드시 **수령 확인 기준**(설계 반영됨)이어야 하고, 발송 기준 마감은 절대 쓰지 말 것.
3. **초대 코드 = 성장 병목** — 1단계에서 크리에이터에게 초대장 n장을 주는 기능은 넣지 말되(품질 통제), 2단계 최우선 후보로. 그레이딩 38°+에게만 초대권 2장을 주면 성장과 품질 통제가 동시에 잡힌다.
