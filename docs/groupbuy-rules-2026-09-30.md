## 0. 한눈에 보기

```
[아르바임/브랜드] 개설 ─→ [호스트] 수락·영상·공유 ─→ [구매자] 발견 → 상세 → 옵션 → 주문서 → 카드 등록(결제 예약)
                                                                              │
                                                            마감 시각 ─→ 판정 ─┼─ 성사: 일괄 결제 → 명단 확정 → [브랜드] 명단 수령·발송·송장 입력 → [구매자] 배송 조회
                                                                              └─ 미달: 결제 없음, 전원 알림
```

역할별 한 줄 규칙
- **구매자**: 마감 전에는 언제든 취소할 수 있다. 돈은 마감 때 목표를 넘은 경우에만 나간다.
- **호스트(인플루언서)**: 수락·한마디·영상·공유만 한다. 가격·물량·배송·CS에는 관여하지 않고 개인정보도 보지 않는다.
- **브랜드**: 조건(가격·수량·기간)을 정해 연다. **결제가 끝난 주문**의 명단만 받고, 직접 발송한 뒤 송장을 입력한다.
- **아르바임(운영)**: 개설 승인·예외 처리·CS·정산을 맡는다. 구매자에 대한 판매 책임 주체(MoR)다.

4. 가격 카드: "공동구매가" · 할인율 · 공동구매가 · 정가(취소선) · "정가보다 ○원 저렴해요" · 배송비 · 발송 예정일
5. 진행 카드: 마감(오픈) 시계 · 진행 막대 · 목표 문구 · 참여자 수 · 최근 참여 3건

9. 호스트: 호스트 카드(한마디) + 호스트 영상

11. 하단 바: 할인율·가격 + 주 버튼

### 1-3. 표시 규칙

| 요소 | 규칙 |
|---|---|
| 할인율 | `round((1 − 공동구매가/정가) × 100)`. 0% 이하면 표시하지 않는다. 정가는 판매자 스토어에 등록된 실제 판매가만 쓴다(허위 정가 금지). |
| 절약액 | 정가 − 공동구매가. 할인율이 없으면 숨긴다. |
| 시계 | 24시간 이상 남으면 "n일 HH:MM:SS", 미만이면 "HH:MM:SS". 1초마다 갱신. 0이 되는 순간 버튼 상태를 다시 계산한다. |
| 진행 막대 | 최소 수량이 0이면 막대를 숨기고 "n개 예약됨"만 표시. 막대 값 = 예약 수량 ÷ 최소 수량(최대 100%). |
| 목표 문구 | 남음 > 0 → "목표까지 n개 남았어요", 0 → "목표 달성! 마감 때 한 번에 결제돼요". |
| 예약 수량 | 카드 등록이 끝난 주문(`RESERVED`)만 센다. 주문서만 쓰고 이탈한 주문은 세지 않는다. |
| 참여자 수 | 예약 완료 주문 건수. **결정 필요:** 3명 미만이면 숨길지(적어 보이는 역효과). 제안: 3명 이상일 때만 표시. |
| 최근 참여 | 최신 3건. 이름은 서버가 첫 글자 + "**"로 가린다. 수량과 상대 시각("5분 전")만 붙인다. |
| 남은 수량 | 최대 수량이 있을 때만 옵션 시트에 표시한다. **결정 필요:** 남은 수량이 20% 이하일 때 상세에도 "마감 임박" 배지. |
| 상세 이미지 | 가로 860px 이상 권장. 원본 비율 그대로(자르지 않음). 처음 1장 + 더보기. |
| 호스트 영상 | 최대 10개. 호스트 본인이 올린 리뷰 영상만. 탭하면 영상 화면. |
| 공개 조건 | 호스트 수락 전(`PENDING_HOST`)은 구매자에게 404. 호스트·브랜드만 미리보기. |

### 1-5. 주문서 규칙
- 필수: 받는 분 이름 · 휴대폰(숫자 9~13자리) · 우편번호(KR 5자리 / JP 7자리) · 주소. 선택: 상세 주소 · 배송 메모(100자).
- 필수 동의 2개: ① 마감 때 목표를 넘으면 등록 카드로 결제 ② 브랜드에 배송 정보 제공(보유: 배송 완료 후 3개월).
- 같은 내용으로 다시 누르면 같은 주문이다(요청 번호). 카드 등록 창을 닫고 다시 누르면 같은 결제창으로 이어진다.
- 옵션 시트에서 고른 옵션·수량으로 시작한다. 다시 불러온 뒤 한도가 줄었으면 수량을 한도 안으로 맞춘다.
- "저장된 배송지 불러오기"로 마이 → 배송지 관리 값을 채운다.

### 1-6. 수량 규칙
- **1인 최대 수량**: 한 계정의 예약 완료 주문 수량 합. 기본 5개. 브랜드가 개설 때 정한다.
- **최대 수량**: 브랜드가 확보한 물량. 0 = 제한 없음. 예약 합이 최대에 도달하면 즉시 모집 종료(조기 마감).
- **최소 수량**: 성사 기준. 0 = 기준 없음(마감 때 예약 전원 결제).
- 카드 등록 전 주문은 수량 계산에서 빠진다. 같은 사람이 새 주문을 만들면 이전 미완료 주문은 대체(취소)된다.

### 1-7. 빈 상태·오류 문구 규칙
- 링크가 틀리거나 비공개 → "공동구매를 찾을 수 없어요. 링크가 만료됐거나 비공개 상태예요."
- 네트워크 → "불러오지 못했어요…" + 다시 시도.
- 결제 실패(한도 초과 등) → 내 공동구매 주문 카드에 사유와 "고객센터로 문의" 안내.
- 사용자에게 내부 코드·영문 오류를 보여주지 않는다.

### 1-8. 고도화 백로그 (우선순위순)
1. ⬜ **앱 없는 사용자용 웹 상세** — 공유 링크 착지 페이지(상품·가격·마감·호스트 영상 썸네일 + "앱에서 참여하기"). 인스타·카톡 미리보기(OG 이미지·제목).
2. ⬜ **일본어 화면** — 공동구매·주문서·내 공동구매·알림 문구. JP 공동구매 상세는 기기 언어가 일본어면 일본어로.
3. ⬜ **주문 상세** — 진행 타임라인(예약 → 결제 → 발송 → 도착), 배송지 확인, 문의하기.
4. ⬜ **공동구매 전체 목록** — 탭: 진행 중 / 오픈 예정 / 종료. 정렬: 마감 임박순(기본) · 할인율순 · 인기순.
5. ⬜ **호스트 수익** — 예상(예약 기준)·확정(결제 기준)·지급.
6. ⬜ 마감 임박 배지, 옵션별 가격, 리뷰(구매자 후기) 탭.

### 2-2. 나가는 곳
- 상세 → 호스트 영상 → 영상 화면(기존). 상세 → 공유 → 시스템 공유 시트(링크 + 제목).
- 주문 완료 → 상세로 복귀. 결제 완료·배송은 **내 공동구매**에서 본다.
- 배송 조회 → 택배사 추적 페이지(외부 브라우저).
- 호스트 관리 → 새 영상 올리기(카메라) → 돌아오면 영상 후보에 바로 보인다.

| 619 | 예약자·호스트·브랜드 | 미달 취소 | "목표에 못 미쳐 취소됐어요. 결제되지 않았어요" | 상세 |
| 620 | 구매자 | 송장 등록 | "상품이 발송됐어요 · 택배사 송장번호" | 내 공동구매 |
| 621 | 브랜드 | 발송 예정일 D-1, D+0(미발송 건 있을 때) | "발송 대기 n건 · 오늘까지 송장을 입력해 주세요" | 브랜드 명단 |

- 한 사람에게 같은 공동구매 알림은 하루 최대 2건(성사·결제·발송처럼 거래 알림은 예외).
- 야간(21:00~08:00) 마케팅성 알림(616·617)은 다음 날 08:00으로 미룬다.

### 2-4. 링크 규칙
- 형식: `https://greyd.app/groupbuy/gb-{소문자 hex 8자리}`. 앱 스킴은 `greyd://groupbuy/gb-…`.
- 링크로 들어온 순간 추적 코드(gb-…)를 기기에 7일 기억한다 → 그 기간의 주문은 이 공동구매·호스트에 귀속.
- 호스트 공유 시 "광고"·"유료 광고 포함" 표기를 안내한다(호스트 관리 화면에 고정 문구).
- 공동구매가 꺼진 빌드(서버 배포 전 스토어 버전)에서는 링크를 열지 않는다. ✅

## 3. 브랜드 명단 전달 규칙

### 3-1. 원칙
1. **결제 완료된 주문만** 명단에 오른다. 예약·카드 미등록·결제 실패·취소·미달 주문은 개인정보가 넘어가지 않는다.
2. 명단은 **마감 판정과 결제가 끝난 뒤 한 번에 확정**된다. 모집 중에는 브랜드에게 숫자(예약 건수·수량)만 보인다. ✅
3. 명단은 **앱·웹의 로그인된 화면에서만** 본다. 개인정보가 담긴 파일을 이메일이나 메신저에 첨부해 보내지 않는다. 알림에는 링크만 넣는다.
4. 브랜드는 배송 목적으로만 쓴다. 보유 기간이 끝나면 명단의 개인정보는 가려진다.

### 3-2. 타임라인

| 시점 | 브랜드가 받는 것 | 방법 |
|---|---|---|
| 모집 중 | 예약 건수·수량·옵션별 수량(개인정보 없음) | 앱 브랜드 명단 화면, 판매자 웹 |
| 마감 시각 | "마감됐어요, 결제 진행 중" | 알림 |
| 결제 완료(보통 마감 후 1시간 이내) | **명단 확정** + "명단이 준비됐어요" 알림(링크) | 알림 → 앱/웹 명단 화면 |
| 결제 완료 ~ 발송 예정일 | 명단 조회·CSV/엑셀 내려받기·송장 입력 | 앱(한 건씩), 웹(일괄 업로드) |
| 발송 예정일 D-1·당일 | 미발송 건 리마인드 | 알림(621) |
| 발송 예정일 + 2일 | 미발송 건 → 아르바임 운영에 자동 보고, 구매자에게 지연 안내 | 콘솔·알림 |
| 배송 완료 + 3개월 | 이름·연락처·주소 가림 처리(주문번호·수량·금액만 남음) | 자동 |

### 3-3. 명단 항목

| 항목 | 예 | 비고 |
|---|---|---|
| 주문번호 | gb-1a2b3c4d-0012 | 송장 업로드 키 |
| 받는 분 | 홍길동 | |
| 연락처 | 010-1234-5678 | |
| 우편번호 | 06236 | 앞자리 0 유지(엑셀에서 텍스트 처리) |
| 주소 · 상세 주소 | 서울 강남구 … · 101호 | |
| 배송 메모 | 문 앞에 놓아주세요 | |
| 옵션 · 수량 | 50ml · 2 | |
| 결제 금액 · 통화 | 42,800 · KRW | 배송비 포함 |
| 결제 시각 | 2026-10-06 12:03 | |
| 택배사 · 송장번호 | CJ · 123456789012 | 브랜드 입력 |
| 상태 | 결제 완료 / 발송됨 | |

- 형식: CSV(UTF-8, 엑셀 호환) ✅. **결정 필요:** 엑셀(.xlsx) 추가 — 우편번호·전화번호 앞자리 0을 확실히 유지하려면 xlsx 권장.
- 옵션별 합계 요약(예: 50ml 34개, 80ml 21개)을 명단 위에 표시한다(물량 준비용). ⬜

### 3-4. 명단 확정 후 변경 규칙
- **주소 변경 요청**: 구매자 → 아르바임 CS. 브랜드가 발송 전이면 명단의 주소를 수정하고, 수정 이력과 "주소 변경됨" 표시를 남긴다. 발송 후에는 택배사 경유로 처리한다.
- **발송 전 취소 요청**: 결제 완료 후 취소는 아르바임이 판단해 전액 환불한다. 명단에서는 "취소됨"으로 바뀌고 발송 대상에서 빠진다. 브랜드에게 알림.
- **재고 부족·일부 발송 불가**: 브랜드가 해당 주문을 "발송 불가"로 표시(사유 필수) → 아르바임이 환불하고 구매자에게 안내. ⬜
- 명단은 **추가되지 않는다**(마감 후 새 주문 없음). 빠지는 건 위 두 경우뿐이다.

### 3-5. 송장 입력 규칙
- 택배사 코드: KR 7곳(CJ·한진·롯데·우체국·로젠·CU·GS), JP 3곳(야마토·사가와·일본우편), 기타. ✅
- 송장번호: 공백·하이픈 제거 후 영문 대문자·숫자 6~30자. 기타 택배사는 형식 검사를 하지 않는다(추적 링크 없음). ✅
- 입력 방법: 앱에서 한 건씩 ✅ / 판매자 웹에서 **CSV 일괄 업로드**(주문번호·택배사·송장번호 3열) ⬜.
- 수정: 발송 후에도 송장 수정 가능. 수정하면 구매자에게 다시 알리지 않고 화면만 바뀐다.
- 모든 결제 완료 주문에 송장이 들어가면 공동구매 상태가 "배송 완료"가 된다. ✅

### 3-6. 보안·개인정보
- 명단 화면 조회, 파일 내려받기, 송장 수정을 **누가·언제** 했는지 기록한다(감사 로그). ⬜ (서버)
- 파일 이름에 개인정보를 넣지 않는다(`groupbuy-gb-xxxx.csv`). ✅
- CSV 셀이 `= + - @`로 시작하면 앞에 `'`를 붙인다(엑셀 수식 실행 방지). ✅
- 호스트는 개인정보를 보지 못한다. 예약 수·결제 수만 본다. ✅
- 판매자 계정 1개당 자기 브랜드의 공동구매 명단만 볼 수 있다(서버 권한 검사). ⬜

## 7. 개발 순서 제안

1. **서버(ops)**: 공동구매 API · 토스 카드 등록/마감 결제 · 명단 확정 · 감사 로그 · 알림 612/614~621
