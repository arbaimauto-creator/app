# 2차 가공 동의 · 인센티브 · 공동구매 설계 (2026-09-16)

대표 지시 요약: 구성은 **사용자**와 **판매자** 둘. 스폰서드·파트너스로 찍힌 리뷰 영상 중 **성과가 좋은 것**을 골라
작성자에게 **2차 가공 동의**를 받는다. 동의의 대가로 둘 중 하나를 고르게 한다.
(1) 2차 가공물로 **판매가 일어나면 인센티브**, (2) 2차 가공물 성과가 기준을 넘으면 **특정 국가 공동구매 개설권 + 공동구매 인센티브**.
인플루언서는 **동의만** 하면 되고 제작·유통·배송·정산은 브랜드·greyd·3PL이 처리한다.
사용자는 **앱**, 브랜드는 **대시보드**에서 전 과정을 본다. 역할은 고정이 아니다 — 누구나 구매자이고 누구나 인플루언서가 될 수 있다.

## 1. 역할 모델

역할은 계정 속성이 아니라 **행동의 결과로 붙는 상태**다. 한 계정이 동시에 둘 다일 수 있다.

| 표면 | 대상 | 정체성 | 비고 |
|---|---|---|---|
| **앱** | 사용자 | 앱 계정(`greydAppId` ↔ ops `Influencer`) | 구매자·리뷰어를 가르지 않는다. 리뷰를 올리면 인플루언서 지표(G-스코어·포인트)가 쌓이고, 구매하면 주문 이력이 쌓인다. |
| **대시보드(웹)** | 판매자(브랜드) | ops 매직링크 토큰(campaign 범위) | 상품 등록·캠페인·2차 가공 요청·공동구매·성과·정산을 여기서 본다. |
| **콘솔(웹)** | greyd 운영 | SSO 오퍼레이터 | 승인·정산 실행·예외 처리. |

앱 안에서 "판매자 모드"는 만들지 않는다. 판매자는 웹이다(D26 결정선, 2026-09-16 상품 등록 웹과 동일).

## 2. 전체 수명주기

1. **원본 리뷰 생성** — 스폰서드/파트너스 캠페인 수행 → 앱에 리뷰 업로드(기존 흐름).
2. **성과 관측** — 앱 내 지표(조회·저장·상품 카드 클릭·구매 전환)와 외부 채널 지표(인스타·틱톡)를 모은다.
3. **후보 선정** — 기준을 넘은 리뷰가 브랜드 대시보드와 콘솔에 "2차 가공 후보"로 뜬다.
4. **동의 요청** — 브랜드(또는 운영)가 요청 → 작성자 앱에 알림. 요청에는 **사용 범위**가 명시된다(매체·기간·국가·편집 범위).
5. **동의 + 베네핏 선택** — 작성자는 앱에서 범위를 확인하고 동의한다. 이때 **A(판매 인센티브)** 또는 **B(공동구매)** 중 하나를 고른다.
6. **2차 가공물 제작** — 브랜드·greyd가 제작(광고 소재, 상세페이지, 숏폼 재편집 등). 작성자는 관여하지 않는다.
7. **배포·추적** — 가공물마다 추적 링크/코드를 붙여 판매를 귀속한다.
8. **정산** — A: 귀속 매출 × 요율. B: 공동구매 성사 시 정해진 인센티브.
9. **(B 경로) 공동구매** — 기준 충족 시 특정 국가에 공동구매를 연다. 모집 → 목표 수량 도달 → 3PL 일괄 배송 → 정산. 미달 시 전액 환불.

## 3. 성과 기준 (측정 가능한 것부터)

지금 측정 가능한 것과 아닌 것을 나눠 둔다. **측정 못 하는 지표를 기준에 넣지 않는다.**

| 지표 | 출처 | 지금 가능? |
|---|---|---|
| 리뷰 조회수·저장수 | 앱 API 서버(videos) | 가능 |
| 상품 카드 클릭 | 앱 이벤트 → 서버 | **추가 필요**(이벤트 없음) |
| 구매 전환·매출 | 앱 API 서버(orders) | 결제 붙은 뒤 가능 |
| 외부 채널 조회·좋아요 | ops `Content.metrics`(운영 입력) | 부분 가능(수동) |

**1차 기준(제안, 조정 가능)**: 최근 30일 내 리뷰 중 `조회수 ≥ 1,000` **또는** `저장수 ≥ 50`.
결제가 붙은 뒤에는 `귀속 매출 ≥ 기준액`을 1순위 기준으로 올린다.

## 4. 베네핏 두 가지

### A. 판매 연동 인센티브
- 가공물에 붙은 추적값(`assetId`)이 주문에 기록되면 그 주문을 해당 작성자에게 귀속한다.
- **요율 기본값(제안)**: 귀속 매출의 3%. 캠페인별로 덮어쓸 수 있다.
- **귀속 기간(제안)**: 클릭 후 7일.
- **지급**: 포인트 원장(`PointLedger`)에 적립 후, 일정액 이상이면 현금 지급(`Payout`) 전환. 세금 처리는 현금 지급 시점 기준.

### B. 공동구매 개설 + 인센티브
- 가공물 성과가 기준을 넘으면 작성자 이름으로 **특정 국가**에 공동구매를 연다.
- 작성자가 하는 일: 동의와 국가 선택뿐. 가격·수량·물류·CS는 브랜드·greyd·3PL이 처리한다.
- **인센티브(제안)**: 공동구매 성사 매출의 5%(A보다 높게 — 모집 기여가 크다).
- **성사 조건**: 최소 수량 미달 시 자동 취소·전액 환불. 기간 기본 14일.

두 베네핏은 **하나만** 고른다. 나중에 바꾸려면 새 동의를 받는다(동의 이력은 남는다).

## 5. 데이터 모델 (ops)

```
SecondaryUseConsent   동의 1건 = (리뷰, 작성자, 브랜드/캠페인) + 사용 범위 + 선택한 베네핏
  reviewId(앱 서버 video id) · influencerId · campaignId · scopeMedia[] · scopeCountries[]
  scopeMonths · editAllowed · benefit(SALES_INCENTIVE | GROUP_BUY) · state(REQUESTED|AGREED|DECLINED|REVOKED)
  requestedAt · decidedAt · revokedAt · termsVersion

RepurposedAsset       2차 가공물 1건 (광고 소재·상세페이지·재편집 숏폼 …)
  consentId · kind · url · trackingCode · publishedAt · state

AssetPerformance      가공물 성과 스냅샷 (일 단위)
  assetId · date · impressions · clicks · orders · revenue

IncentiveGrant        인센티브 확정 1건 (A·B 공통)
  consentId · assetId? · groupBuyId? · basisAmount · rate · amount · currency
  state(PENDING|APPROVED|PAID) · pointLedgerId? · payoutId?

GroupBuy              공동구매 1건
  consentId · productRef(앱 서버 product id) · countries[] · price · minQuantity
  startsAt · endsAt · state(DRAFT|OPEN|REACHED|FAILED|SHIPPING|DONE) · threePlRef
```

`SellerProduct`(2026-09-16)와 이어진다. 공동구매는 등록된 상품을 대상으로만 연다.

## 6. 화면

**앱(사용자)**
1. 알림·활동에 "2차 가공 요청" 카드.
2. 동의 화면 — 사용 범위(매체·국가·기간·편집)를 평문으로 보여주고, 베네핏 A/B를 고르는 화면. 거절도 같은 무게로 배치.
3. 내 2차 가공 현황 — 동의한 건, 가공물, 발생한 인센티브, 지급 상태.
4. 공동구매 화면 — 내 공동구매 진행률(모집 수량·남은 기간), 성사/실패 안내.
5. 마이페이지 포인트·정산 화면에 인센티브 항목 추가.

**대시보드(판매자)**
1. 2차 가공 후보 목록(성과순) → 동의 요청 보내기.
2. 동의 현황과 사용 범위 확인(범위 밖 사용 방지 안내).
3. 가공물 등록·추적 링크 발급, 성과 대시보드.
4. 공동구매 개설·진행·정산.
5. 인센티브 정산 내역.

**콘솔(운영)**
- 동의·가공물·공동구매·정산 승인과 예외 처리, 3PL 상태.

## 7. 법·정산에서 먼저 정해야 할 것

1. **이용허락 범위 기본값** — 매체(자사몰·마켓·유료광고), 기간(제안 12개월), 국가, 편집 범위(자막·길이 편집 허용, 얼굴 합성 금지 등). 동의 문구의 버전을 남긴다.
2. **초상권·출연자** — 영상에 제3자가 등장하면 별도 동의가 필요하다. 요청 전 체크 항목으로 둔다.
3. **유료광고 표시** — 2차 가공물이 광고로 쓰이면 표기 의무는 브랜드에 있다.
4. **인센티브 과세** — 현금 지급은 기타소득·사업소득 구분과 원천징수가 필요하다. 포인트 적립 단계에서는 발생하지 않게 설계한다.
5. **공동구매 책임 주체** — greyd가 판매자(MoR)이므로 청약철회·환불·CS 책임이 greyd에 있다. 미달 시 자동 전액 환불을 규정에 넣는다.
6. **국외 배송·통관** — 3PL 계약과 국가별 수입 규제(화장품·식품은 국가별 인증)를 상품 등록 시 확인한다.

## 8. 단계

### P1 — 동의 루프 (앱 + ops만으로 가능, 지금 착수 가능)
- ops: `SecondaryUseConsent` 모델, 브랜드 대시보드의 후보 목록·요청, 콘솔 승인.
- 앱: 요청 알림, 동의 화면(범위 + 베네핏 선택), 내 현황 화면.
- 채널: 기존 `/api/mobile/*` 확장(`consents` 조회·응답).
- 성과 기준은 1차 기준(조회수·저장수)으로 시작한다.

### P2 — 가공물·추적·인센티브 A
- `RepurposedAsset`·`AssetPerformance`·`IncentiveGrant`, 추적 코드 발급.
- 주문에 `assetId` 귀속 기록 → **앱 API 서버 변경 필요**(주문 생성 시 추적값 저장).
- 포인트 적립 → 현금 전환.

### P3 — 공동구매 B
- `GroupBuy` 모델, 앱 공동구매 화면, 모집·성사·환불, 3PL 연동.
- 결제가 붙어 있어야 의미가 있다(2026-09-16 Stripe 작업의 후속).

## 9. 지금 막힌 것

1. **앱 API 서버 접근** — 판매 귀속(P2)·공동구매 주문(P3)은 서버 변경이 필요하다. 저장소 권한 대기 중.
2. **ops 배포 승인** — 동의 루프(P1)는 ops 스키마 변경이 필요하다. 배포는 승인 후.
3. **정책값 확정** — 성과 기준 수치, 인센티브 요율(3%/5% 제안), 이용허락 기간(12개월 제안), 공동구매 최소 수량·기간·국가.

위 값들은 문서의 제안값으로 먼저 구현하고, 확정되면 설정으로 바꾼다.
